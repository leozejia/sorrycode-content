# WorkBuddy 的权限与工作空间

WorkBuddy 不只是聊天工具。它可以读取和写入本地文件，也可能调用脚本或外部程序。开始任务前先选对工作空间，并保持默认权限，比写一段很长的提示词更重要。

<h2 id="workspace">工作空间是什么</h2>

工作空间是当前任务主要读取和保存文件的文件夹。你可以在“新建任务”的输入框下方点击“选择工作空间”。

推荐为每类任务准备独立目录：

```text
WorkBuddy-Tasks/
  meeting-notes/
  spreadsheet-cleanup/
  report-draft/
```

只把本次需要处理的文件副本放进去。不要第一次就选择整个桌面、下载目录、个人主目录、生产项目或唯一一份重要资料。

<h2 id="default-permission">默认权限</h2>

“默认权限”是日常任务的推荐模式。WorkBuddy 会在安全沙箱约束内执行，超出范围或遇到高风险动作时请求你的允许。

通常需要重点检查：

- 写入工作空间之外的目录
- 删除、覆盖或批量移动文件
- 执行脚本、命令或外部程序
- 访问网络或敏感配置
- 读取凭证、密钥和系统目录

确认前先看操作内容、目标路径和影响范围。不确定时点取消，再让 WorkBuddy 先给出文件清单、改名预览、脚本内容或回退方法。

<h2 id="full-access">什么时候才用完全访问</h2>

“允许完全访问”会减少或跳过高风险操作的逐步确认。它不会让模型更聪明，只会把更多操作直接交给模型执行。

只有同时满足这些条件时才短时间开启：

- 任务发生在隔离、可删除的测试目录
- 所有输入文件都有副本或版本控制
- 你理解任务将运行的脚本和命令
- 即使任务执行错误，也不会影响生产数据、个人资料或系统配置

任务完成后切回默认权限。

不要在客户资料、财务资料、唯一文件副本、生产项目、个人主目录或包含凭证的目录中开启完全访问。

<h2 id="safe-prompt">先预览，再执行</h2>

涉及批量操作时，可以先这样说：

```text
先不要修改文件。读取当前工作空间后，列出你准备执行的步骤、涉及的文件、修改前后对照和回退方法。等我确认后再执行。
```

批量重命名时：

```text
先生成旧文件名和新文件名的对照表，不要实际改名。发现重名、无法识别或格式异常的文件时单独列出，不要猜。
```

生成文档时：

```text
把结果写入一个新文件，不要覆盖原文件。完成后报告输出路径和你没有处理的内容。
```

<h2 id="backup">备份和回退</h2>

默认权限不是备份系统。重要任务开始前至少做一项：

- 复制一份输入文件到测试目录
- 使用 Git 或云盘历史版本
- 让 WorkBuddy 输出新文件，不覆盖原文件
- 批量修改前保存一份对照表

WorkBuddy 的具体备份能力会随系统和版本变化，不要把它当作唯一回退手段。

<h2 id="credentials">不要把凭证放进工作空间</h2>

API Key 应保存在 WorkBuddy 的模型设置中，不应写入任务提示、Markdown、表格、截图或项目文件。

工作空间中如果包含 `.env`、证书、SSH Key、支付资料或客户隐私文件，先移走或改用不含敏感信息的副本。安装第三方 Skill 前，也要检查来源、脚本和它要求访问的数据。

<h2 id="recommended-default">推荐默认值</h2>

| 场景 | 权限 | 工作空间 |
| --- | --- | --- |
| 第一次使用 | 默认权限 | 新建空测试目录 |
| 文档、表格、资料整理 | 默认权限 | 只放本次文件副本 |
| 批量重命名或移动 | 默认权限 | 先预览并保留对照表 |
| 可信脚本反复运行 | 默认权限；隔离环境中可临时完全访问 | 可删除的测试目录 |
| 生产资料或唯一副本 | 默认权限 | 不建议直接交给 WorkBuddy 修改 |
