# 理解模型能力

选择模型不只是看价格和速度，更重要的是理解每个模型的核心能力和限制。

## 核心能力维度

### 1. 代码理解

**什么是代码理解**：
- 读懂现有代码结构
- 理解代码意图
- 追踪依赖关系
- 识别潜在问题

**不同模型的表现**：
- **强**：Claude Opus, GPT-Sol
- **中**：Claude Sonnet, GPT-Astra
- **弱**：快速模型（Haiku, Flash）

**何时重要**：
- 重构大型项目
- 代码审查
- Bug 定位
- 架构分析

### 2. 代码生成

**什么是代码生成**：
- 根据需求写新代码
- 实现特定功能
- 遵循代码风格
- 处理边界情况

**不同模型的表现**：
- **强**：Claude Opus, GPT-Sol, Claude Sonnet
- **中**：DeepSeek, Gemini
- **弱**：快速模型

**何时重要**：
- 功能开发
- 原型实现
- 工具脚本
- 测试用例

### 3. 推理能力

**什么是推理**：
- 多步骤问题解决
- 权衡多种方案
- 逻辑推导
- 复杂决策

**不同模型的表现**：
- **强**：GPT-Sol (支持 ultra), Claude Opus
- **中**：Claude Sonnet, GPT-Astra
- **弱**：快速模型

**何时重要**：
- 架构设计
- 算法选择
- 性能优化
- 技术决策

### 4. 响应速度

**什么影响速度**：
- 模型大小
- 推理复杂度
- Reasoning effort 设置
- 网络延迟

**不同模型的表现**：
- **快**：Haiku, Flash, Luna, Gemini Flash
- **中**：Sonnet, DeepSeek, Astra
- **慢**：Opus, Sol（尤其 max/ultra effort）

**何时重要**：
- 交互式开发
- 大量简单任务
- 实时反馈
- 高并发场景

### 5. 上下文理解

**什么是上下文理解**：
- 记住对话历史
- 理解项目全局
- 跨文件关联
- 长期一致性

**不同模型的表现**：
- **强**：GPT-Sol (1M+ tokens), Opus
- **中**：Sonnet, GPT-Astra
- **弱**：快速模型（窗口较小）

**何时重要**：
- 大型项目重构
- 长对话调试
- 多文件修改
- 需要全局理解

### 6. 指令遵循

**什么是指令遵循**：
- 理解用户意图
- 按要求格式输出
- 遵守约束条件
- 不做多余操作

**不同模型的表现**：
- **强**：Claude 系列（出名的好）
- **中**：GPT 系列
- **弱**：某些国产模型

**何时重要**：
- 需要特定格式
- 有严格约束
- 自动化工作流
- 批量处理

## Reasoning Effort 的影响

### 什么是 Reasoning Effort

模型在回答前的"思考深度"：

- **low/minimal** - 快速响应，简单推理
- **medium** - 平衡思考，常规任务
- **high** - 深度思考，复杂任务
- **xhigh/max** - 最深思考，最复杂任务
- **ultra** - GPT-Sol 独有，极限推理

### 如何选择 Effort

| 任务复杂度 | 推荐 Effort | 说明 |
|-----------|------------|------|
| 简单修改 | low/medium | 节省成本和时间 |
| 日常开发 | medium/high | 平衡质量和速度 |
| 复杂重构 | high/xhigh | 质量优先 |
| 架构设计 | xhigh/max | 最高质量 |
| 理论推导 | ultra (GPT-Sol) | 极限推理 |

### 成本影响

Reasoning effort 会显著影响成本：

- **low** - 基础价格
- **medium** - 约 1.5x
- **high** - 约 2-3x
- **xhigh** - 约 3-5x
- **max** - 约 5-10x
- **ultra** - 约 10-20x

**建议**：
- 不要默认用最高 effort
- 根据任务复杂度调整
- 简单任务用 low/medium

## 模型限制

### 上下文窗口

**限制**：模型能"看到"的内容量

**典型大小**：
- GPT-Sol: 1M+ tokens
- Claude Opus: 200k tokens
- Sonnet/Haiku: 200k tokens
- DeepSeek: 64k-128k tokens

**影响**：
- 大项目可能装不下
- 长对话会被截断
- 跨文件理解受限

**应对**：
- 用更大窗口的模型
- 分批处理
- 只提供相关文件

### 输出长度

**限制**：模型能生成的最大内容

**典型限制**：
- GPT-Sol: 128k tokens
- Claude 系列: 16k-64k tokens
- 其他: 4k-16k tokens

**影响**：
- 大文件生成可能被截断
- 长输出需要分批

**应对**：
- 分批生成
- 请求具体部分
- 使用输出更大的模型

### 知识截止

**限制**：模型训练数据的时间点

**影响**：
- 不知道最新技术
- 可能使用过时方法
- 新框架不了解

**应对**：
- 提供文档链接
- 使用 web search 工具
- 人工补充信息

### 特定能力缺失

某些模型不支持：
- 图片输入/生成
- 工具调用
- 流式输出
- 某些语言

**应对**：
- 查询模型能力
- 选择支持的模型
- 使用专用模型

## 实际测试

### 如何测试模型能力

**步骤**：

1. **选择代表性任务**
   - 不要太简单
   - 不要太复杂
   - 能体现核心能力

2. **用不同模型执行**
   ```bash
   magpie claude sorrycode/claude-opus-5-5
   # 执行任务，记录结果
   
   magpie claude sorrycode/claude-sonnet-5-5
   # 执行同样任务，对比
   ```

3. **评估多个维度**
   - 代码质量
   - 完成时间
   - Token 消耗
   - 需要修改次数
   - 理解准确度

4. **记录结果**
   - 建立模型能力档案
   - 为后续选择提供依据

### 测试示例

**任务**：重构一个 200 行的函数

**Opus 结果**：
- 时间：90s
- 质量：优秀（无需修改）
- 理解：完全理解意图
- 成本：$0.80
- 评分：⭐⭐⭐⭐⭐

**Sonnet 结果**：
- 时间：45s
- 质量：良好（需要一次微调）
- 理解：理解主要意图
- 成本：$0.30
- 评分：⭐⭐⭐⭐

**Flash 结果**：
- 时间：20s
- 质量：可用（需要两次修改）
- 理解：理解基本意图
- 成本：$0.08
- 评分：⭐⭐⭐

**结论**：日常重构用 Sonnet 性价比最高

## 常见问题

### Q: 最强的模型是哪个？

**A**: 没有"最强"，只有"最合适"。

- 代码理解：Claude Opus
- 推理能力：GPT-Sol (ultra)
- 响应速度：Haiku, Flash
- 性价比：Sonnet, DeepSeek

### Q: 如何知道模型的真实能力？

**A**: 实际测试。

- 不要只看宣传
- 用你的任务测试
- 建立能力档案

### Q: Reasoning effort 越高越好吗？

**A**: 不是。

- 简单任务用高 effort 浪费
- 成本呈指数增长
- 时间也更长

**建议**：
- 简单任务：low/medium
- 日常任务：medium/high
- 复杂任务：high/xhigh
- 极难任务：max/ultra

### Q: 如何快速判断模型能力？

**A**: 看名称和层级。

**高能力**：
- `opus` - Claude 最强
- `sol` - GPT 推理最强
- `pro/prime` - 高级版

**快速但能力弱**：
- `haiku` - Claude 最快
- `flash` - 快速版
- `luna` - GPT 快速版

### Q: 能力会随时间变化吗？

**A**: 会。

- 厂商持续优化
- 新版本能力更强
- 旧版本可能弃用

**建议**：
- 定期重新测试
- 关注更新日志
- 动态查询新模型
